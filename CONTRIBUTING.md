# Contributing

## Changes

1. Open an issue or define a small task with acceptance criteria.
2. Create a short-lived feature branch; do not commit directly to a protected main branch.
3. Add tests, update relevant documentation, and keep the change focused.
4. Open a pull request using the repository template; record requirements and test evidence.
5. Obtain review and required approvals before merging or deploying.

## Security and confidentiality

Do not submit real client/employee/donor data, credentials, or production logs. Use synthetic fixtures.
Report vulnerabilities privately as described in [SECURITY.md](SECURITY.md).
